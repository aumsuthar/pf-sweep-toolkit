# Failure modes — phase-field stress sweeps

Hard-won notes. Every item here cost a failed run or a wasted day. Read before
touching anything in this directory.

---

## 1. Orientation

- GPU phase-field sim of stress-induced martensitic transformation in NiTi.
  OpenACC + cuFFT + cuRAND, built with `nvc`, run via SLURM (SLURM account set per site).
- **Compile-time grid** is `L`/`M`/`N` in `constants.h`. The physical box is
  **always 640 nm**, so the cell size follows the grid:
  - `128` → 5.0 nm/cell   (the configuration these notes describe)
  - `256` → 2.5 nm/cell   (matches `sele1/2/5/6`)
  Changing the grid changes the *physical interface width*, because `keta`
  (0.008) is in grid units. Results at 128³ compare to `sele3/4/7/8`, not to
  `sele1/2/5/6`.
- **Applied stress: `STRESS_MAG` × 50 = MPa.** So 20 → 1000 MPa.
- `STRESS_MAG` is a `#define` in `inhom_v3.c` — every stress level needs its own
  recompile. That is why the sweep is sequential, not parallel.

## 2. The concentration field (CM)

- CM = **Concentration Modulation**: `c(y) = avg + amp*sin(2*pi*y/lambda)`,
  modulation along **+y**, x fastest. See the local `make_cm.py`.
- It is read into **`conc`**, NOT `c_r` — `initialization.c:38`, path is
  **hardcoded**, so switching CM means editing that line and recompiling.
- `conc` feeds `xNi` in `compute_mur_eta` (`time_evolution.c:306`), setting the
  local transformation driving force.
- **`c_r` is unused** in this configuration. `c_avg = 0.000000` in every MT log
  is expected, not a bug.
- **Composition does not evolve.** The Cahn-Hilliard block in `GetEintC` is
  inside `/* */` (`time_evolution.c:34-49`). The CM is a *static parameter
  field*. Anything wrong with it (mean offset, a step at the wrap plane) is
  permanent for the whole run — nothing diffuses it away.
- Under periodic BCs the box can only hold `lambda = 640/n`. A non-ladder
  wavelength shifts the realized mean off `avg` (up to +0.43 at% for 1280 nm)
  and leaves a composition step at the y-wrap plane. User decided (Sep 2026) to
  keep the sweep wavelengths as sampled — **do not re-propose snapping.**

## 3. Input VTK rules — both of these will bite

**Every header line must be under 39 characters.** `init_from_file`
(`io.c:187`) skips the header with `char ignore[40]; fgets(ignore,40,fp)`. A
longer line takes two `fgets` calls, the 4-line skip lands short, and the
`DIMENSIONS` parse reads stack garbage:

```
#Error:Input file size (0,0,538976288) is different from the expected size (128,128,128)
```

`538976288` = `0x20202020` = four spaces. Keep the line-2 comment short
(`CM set1 pt01`). `Generated by MATLAB` is 19 chars, which is why the sele
files never tripped it.

**File dimensions must match the compiled grid.** A 128³ file in a 256³ build
reads 2.1M of the expected 16.8M values. `conc/sele1,2,5,6` are 256³;
`sele3,4,7,8` are 128³.

## 4. Failures look like successes — always verify output

`Void_model.exe` calls **`exit(0)` on its error paths**. SLURM records
`COMPLETED, ExitCode 0:0` for a run that did nothing. A sweep will happily
chain the next step against nonexistent input.

- Never trust job state. Check that `output_files/eta_pure_<label>_*_t*.vtk`
  exist. `run_stress_sweep.sh` now does this and aborts the chain.
- The real error text is in the SLURM `.o` file, not the MT log.

## 5. eta chaining — the 3-subscript trap

The four real chaining calls use the **4-subscript** form:

```c
	sprintf(filename,"input_files/eta_pure_<label>_<v>_t15000.vtk");
	init_from_file(&eta_r[0][0][0][0],filename);   /* 4 subscripts = real */
```

There are **3-subscript leftovers** (`&eta_r[0][0][0]`) elsewhere in
`initialization.c` that must stay commented. One at line ~27 sits *before* the
`conc` read, so if uncommented it fires with `filename` unassigned:

```
#Error: the file  could not be opened for reading      <- note the empty name
```

Any sed touching these lines **must** match `&eta_r\[[0-9]\]\[0\]\[0\]\[0\]`.
After editing, `diff initialization.c initialization.c.bak` — the only expected
changes are the `conc` path and the 8 chaining lines.

If the eta lines stay commented, the run silently starts from
`initial_condition1()` = **pure austenite**. Signature: unloading gives
`vf = 0.000000` and a perfectly linear strain-vs-stress line through the
origin. That cost a full day of compute.

## 6. sed hygiene (this caused the worst bug)

A backslash line-continuation **inside single quotes is literal**, not a
continuation. This silently produces a malformed sed script that does nothing:

```bash
sed -i 's|a|b|; \          # BROKEN - the backslash+newline is data
        s|c|d|' file.c
```

Use separate single-line `sed` calls, then **verify the result with grep**
rather than trusting a log message that says it worked.

Related: `set_output_label` rewrites the MT redirect in `slr_run.sh`. Its
pattern must match whatever prefix is actually there. Using a custom prefix
(`MT_s1p01_load0`) against a pattern expecting `MT_load<N>` meant the redirect
never advanced and **all 12 jobs wrote to the same MT file**, destroying every
per-step stress-strain point. The sed is now `s|> MT_.*$|> MT_s1p01_${label}|`.

## 7. Running the sweep

```bash
# loading then unloading, one shot
nohup setsid flock -n /tmp/s1p01_cycle.lock bash run_load_unload.sh \
      > cycle.log 2>&1 < /dev/null & disown

# one branch only (env overrides)
nohup setsid env SWEEP_LEVELS="18 16 14 12 11 9 7 4 2 0" \
      SWEEP_INIT_STRESS=20 SWEEP_FRESH_START=0 \
      bash run_stress_sweep.sh > unload.log 2>&1 < /dev/null & disown
```

- `SWEEP_FRESH_START=1` only for a loading run starting from austenite.
  Unloading **must** be `0` so step 0 chains from the loaded state.
- `module load nvhpc/24.11` is inside the script — nothing in `.bashrc` loads
  it, so an unattended run fails at `make` without it.
- **Never edit `run_stress_sweep.sh` while it is running.** bash reads scripts
  incrementally by byte offset; an edit makes a live instance resume at a
  shifted offset and execute garbage.
- Launch in its own command, ending with `exit 0`. Do **not** put a `sleep` or
  follow-up checks in the same SSH command — it hangs, times out, and a retried
  command starts a **second instance** that races the first (two supervisors
  writing one log = corrupted binary log, duplicate job submissions).

## 8. Process management

- **`pkill -f run_stress_sweep.sh` matches your own command line** and kills the
  shell running the kill. Use exact argv instead:
  ```bash
  ps -eo pid,args --no-headers \
    | awk '$2=="bash" && $3=="run_stress_sweep.sh" {print $1}' | xargs -r kill
  ```
- **`ps` is unreliable here** — OSC round-robins login nodes, so a new SSH
  session may not see the supervisor at all. An "instances: 0" reading is *not*
  proof it died. `squeue`/`sacct` and the log are cluster-wide truth.
- The supervisor's TERM trap **cancels the queued job** on the way out. So:
  empty queue + incomplete chain = supervisor died, and nothing is orphaned.
  Login-node reaping has killed it twice.

## 9. Walltime

- 128³ runs take **~10 minutes**. 256³ is ~8x that.
- Request **00:45:00** for 128³ (user's chosen value — do not trim it without
  being asked). 256³ used 01:35:00.
- A pending job's limit can be lowered in place, no resubmit, and it improves
  backfill immediately:
  `scontrol update jobid=<id> TimeLimit=00:20:00`

## 10. Storage

- Quota is **500 GB** and it has been hit.
- The bulk is intermediate timesteps: each label saves t0/3000/6000/9000/
  12000/15000, and **only t15000** is chained or used for figures. Pruning the
  five intermediates in `sele1/2/5/6` freed 247 GB.
- Keep always: `*_t15000.vtk`, all `MT_*` logs (tiny, and they are the
  stress-strain data), `input_files/` seeds.
- `Sig*_void1_t*.vtk` have **no label in the filename**, so each step
  overwrites the previous one. Only the last step's stress fields survive.

## 11. Physics sanity checks

For `set1_pt01` (avg 51.00%, lambda 400 nm, amp ±0.56%) at 128³:

| STRESS_MAG | MPa  | strain  | vf    |
|-----------:|-----:|--------:|------:|
| 0          |    0 | 0.00018 | 0.006 |
| 15         |  750 | 0.01950 | 0.175 |
| 20         | 1000 | 0.04617 | 0.880 |
| 36         | 1800 | 0.06470 | 0.994 |

- **The transformation happens at 750-1000 MPa.** The `V1_stress`/`V3_stress`
  columns in the sweep CSVs (1421/1746 MPa) are **not** the applied critical
  stress — do not use them to place stress steps. Use a coarse scan first.
- A healthy unload step keeps a high `vf` at the top of the branch. `vf = 0`
  right after a loaded state means the chaining broke (see §5).
